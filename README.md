# dsh-weread

在 DeepSeek Harness 里读微信读书。右侧边栏多出一个「微信读书」标签页：在读、书架、划线笔记、设置；同时把同一份阅读数据注册成 Agent 工具，模型可以在你读书时引用你的进度和划线。

## 能力

| 位置 | 内容 |
| --- | --- |
| 侧边栏 · 在读 | 最近在读的书、封面、阅读进度；「在 DSH 里读」直接在侧边栏渲染正文，「官方阅读器」在内置浏览器打开官方页面 |
| 侧边栏 · 阅读器 | 章节正文（EPUB/TXT 双格式）、上一章/下一章、目录跳转、**回到上次读到的章节**；「外观」可选主题（跟随 DSH / 浅色 / 深色 / 羊皮纸）、字号、行距、字体，全部持久保存；阅读时长按时上报；可选「同步进度」立即回写微信读书 |
| 侧边栏 · 书架 | 电子书 + 有声书/专辑，按最近阅读排序，点开看简介、目录、书籍详情 |
| 侧边栏 · 笔记 | 笔记概览（划线/想法/书签数 + 进度），点开按章节看划线原文与想法 |
| 侧边栏 · 设置 | 填 API Key 与阅读器 Cookie，切换「进度回写」，保存并测试连接 |
| Agent 工具 | `weread_current`、`weread_shelf`、`weread_notes`、`weread_stats`、`weread_search` |

数据来自微信读书官方 Agent Gateway（`https://i.weread.qq.com/api/agent/gateway`），API Key 在
<https://weread.qq.com/r/weread-skills> 领取，绑定你的账号身份。

官方网关**不返回章节正文**，所以侧边栏的原生阅读器走的是另一条链路：用你自己已登录的
weread.qq.com 网页会话（Cookie）请求阅读页与章节分片，并在本地解码成纯文本渲染。
这条链路只在渲染你自己的、你有权限阅读的内容时使用，正文不会离开本机。

## 两条数据链路

| | 官方 Agent Gateway | 网页阅读器 |
| --- | --- | --- |
| 凭据 | API Key（`wrk-…`） | 网页 Cookie（须含 `wr_vid`、`wr_skey`） |
| 提供 | 书架、进度、划线笔记、统计、搜索、点评 | 章节正文、目录、进度回写 |
| 是否必需 | 书架/笔记/统计需要 | 只有在侧边栏读正文时需要 |
| 端点 | `i.weread.qq.com` | `weread.qq.com` |

两者互相独立：只有 Cookie 也能读正文（目录走网页接口），只有 API Key 也能用书架与笔记。

## 安装

```sh
dsh plugin --profile desktop add /absolute/path/to/dsh-weread
```

或者在 DSH 内直接用 `plugin_manager` 的 `install_bundle`，`target` 传这个目录的绝对路径。

**首次安装后需要完全退出并重启 DeepSeek Harness**：客户端半边由 HMR 热加载，但宿主半边是
进程内模块，替换已加载包的代码必须重启才能加载新的 JavaScript 模块代（官方 `host-plugin.md`
的明确约定）。重启后 `index.js` / `lib/` 的改动同样需要重启才生效，`client.js` 的改动会自动热加载。

## 架构

```
client.js                      侧边栏标签页（React，手写 loader 格式，热加载）
  └─ fetch('/api/weread')      ──┐
index.js                         │  宿主半边
  ├─ lib/rpc.js                  │  exact-Fetch 路由，挂在应用自带的 /api 桥上
  │     └─ /api 已代做浏览器信任与鉴权，本路由无需自建
  ├─ lib/service.js  ────────────┘  唯一的数据/操作实现
  ├─ lib/gateway.js                微信读书官方 Agent Gateway
  ├─ lib/store.js                  凭据（0600）+ 响应缓存
  └─ lib/tools.js                  5 个 Agent 工具（与面板共用同一 service）
```

面板与 Agent 工具调用的是**同一个 service 方法**，所以两条路径的行为不会漂移。

## 配置

`cordis.patch.yml` 里的默认值：

| 键 | 默认 | 含义 |
| --- | --- | --- |
| `skillVersion` | `1.0.5` | 每次请求携带的 `skill_version`；官方提示升级时会显示在设置页 |
| `syncProgress` | `true` | 进度回写的**初始**默认值；面板里的开关会覆盖它，并立即生效，无需改文件 |
| `requestTimeoutMs` | `20000` | 单次网关请求超时 |
| `dataDir` | `$DSH_HOME/storages/weread` | 凭据与缓存目录 |

API Key 与 Cookie 不在配置里，而是从侧边栏「设置」写入 `$DSH_HOME/storages/weread/credentials.json`（权限 0600）；
面板里选的偏好——进度回写开关、阅读外观（主题/字号/行距/字体）——写入同目录的 `settings.json`，与凭据分开存放，跨重启保留。

## 为什么官方阅读器的主题/字体每次都会重置

如果你用「官方阅读器」按钮在内置浏览器里打开微信读书并设了主题、字体，那些设置会**每次启动应用都回到默认**，
而且需要重新登录。这不是插件的问题，也不是微信读书的问题，而是 DSH 的隔离设计：

内置浏览器的访客会话分区名是 `dsh-sidebar-browser-<随机 UUID>`（见应用主进程 `lib/main.js`），
**没有 `persist:` 前缀**，在 Electron 里这意味着一个进程内存在型会话——退出即丢弃。注释里也写明它是
"process-lifetime partition"。微信读书的登录态与外观设置都存在该分区的 localStorage 里，于是随分区一起消失。
同一份代码里账号浏览器用的是 `persist:` 前缀，说明这是刻意的区别对待，插件侧无法改变。

所以**要长期保留阅读设置，请用本插件的原生阅读器**（「在读 → 在 DSH 里读」）：它的主题、字号、行距、字体
存在 `settings.json` 里，重启后仍在，也不需要重新登录。

## 已知边界

- 原生阅读器渲染的是纯文本段落：图片、脚注链接与官方阅读器的排版不会保留。
- 官方阅读器（内置浏览器）的登录态与外观设置不跨重启保留，原因见上一节；原生阅读器的外观设置保留。
- 进度回写默认**开启**，可在「设置」里随时关闭；它是账号写操作。
- **面板里显示的进度是官方数值**（直接读 `/book/getprogress`），没有误差。
- **写回时**发送的百分比是本地估算：按各章字数加权，再加上你在当前章节内的阅读位置。
  这个模型用书架上 44 本有阅读位置的书拟合过——被它替换掉的「按章序」模型平均绝对误差
  12.2 个百分点、只有 20% 的书落在 2 个百分点内；现在是 4.6 和 75%。混合两者的网格搜索
  把章序权重推到了 0，即掺入章序只会更差。
- **但真正决定官方数值的是位置，不是这个百分比。** 实测把 `pr` 报成 5、位置不动，
  微信读书存回来的仍是它自己的 17 —— 它按章节与章内偏移自行计算。
  所以 `reportProgress` 会一并上报真实的章节与章内位置，而章内位置是按**段落累计字数**
  换算的，不是滚动条比例：中文段落长短悬殊，滚动比例可能把 17% 的正文报成 86%。
- 网页阅读器的 Cookie 会随请求轮换并被自动保存；若长期不用导致登录失效，需重新粘贴。
- 官方网关没有「全文检索书籍内容」能力，`weread_search` 搜的是书城，不是书内文字。

## 重新打开时回到上次读到的位置

阅读器会记住每本书读到哪一章，下次打开直接回到那里。这个记忆存在本地
`settings.json` 的 `positions` 里（最多 200 本，最久未读的会被淘汰）。

为什么不直接用微信读书自己的进度：**它的位置只在回写成功后才前进**。如果你没开
「进度回写」、或还没到自动上报的时机，服务端记住的仍是旧位置；对一本刚打开、
服务端还处于 `chapterUid: 0` 的书，就只剩「第一章」这一个选择——这正是「每次打开
都是第一章」的成因。所以打开顺序是：**本地记忆 → 微信读书进度 → 第一个有正文的章节**。

## 阅读时长是怎么算的

官方阅读器会记录你的阅读时长；本插件用**同一个字段**（`rt`）上报。实测：上报 60 秒后，
微信读书的今日统计 3006 → 3066 秒、本月 39032 → 39092 秒，**正好 +60 秒**。所以时长确实进你的统计。

但与官方阅读器的计时方式不同，这里按「有效阅读」计算：

- **只在页面可见、且 60 秒内有过交互时才计时**。墙钟时间不等于阅读时间——面板会一直挂载着，
  人走开时开着标签页不算阅读。
- **累计满 2 分钟自动上报一次**；切换章节、离开阅读器时也会把剩余时长补齐。
- 工具栏的「同步进度」按钮随时手动上报（不计门槛，位置也会一并同步）。
- 阅读器顶部显示的「本次已读 X 分钟」就是**尚未上报**的累计时长。

时长上报同样受「进度回写」开关控制；关掉它，位置和时长都不会写回。

## 凭据与隐私

- API Key 只发送给 `i.weread.qq.com`。
- Cookie（可选）只发送给 `weread.qq.com`，用于后续的章节正文读取。
- 所有数据都留在本机，插件不做任何遥测。
